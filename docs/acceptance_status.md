## Новая воспроизводимая геометрическая проверка (после исправления runtime)

- Понижена и закреплена версия Open3D 0.19.0 в основном e2e workflow: реальная full-frame TSDF-карта из оценённых VO+pose-graph поз — 11 478 вершин / 20 532 граней; 596/596 кадров. GitHub Actions: 40713659539.
- Для проверки обобщения внутри сцены построена **другая** карта из **298 чётных кадров**, при этом 298 нечётных RGB-D кадров не использовались для TSDF-интеграции.
- Независимое измерение по удержанным кадрам: 468 722 семплированные точки глубины, медианная дистанция до реконструированной поверхности **0,03103 м**, покрытие не более 5 см — **84,60%**, не более 10 см — **98,40%**, средняя дистанция **0,03517 м**. GitHub Actions: 40746269127.
- Эта проверка подтверждает **same-sequence held-out depth consistency**, но **не** независимую точность 3D-сетки по внешней 3D GT, безопасность навигации и корректность физических instance-ID.
- По TUM fr1_desk собственный RGB-D PnP+pose graph (без GT во входе) показал ATE RMSE **0,05498 м**, RPE@30 **0,04777 м**, 9 проверенных loop constraints. Это baseline для одной сцены, а **не RTAB-Map** и не универсальная оценка SLAM.
- Реальный SmolVLM-256M-Instruct выдал описания для 6 объектных views; 2 не согласовались с классом и были отклонены. Это доказывает только вызов модели и проверку форматной/лексической согласованности, а не семантическую точность по GT.
- Проверка identity consistency по 2 541 реальному наблюдению: высокострогие кросс-визитные условия отобрали 6 794 пар наблюдений с одним назначенным ID. Отсутствие обнаруженных кандидатов split **не доказывает** отсутствия дубликатов: выборка пар ограничена 3D/appearance gates. Отдельный GT physical-ID benchmark по-прежнему обязателен.

**Реестр отдельных PASS-проверок:** config/acceptance.json; все обязательные блокирующие статусы остаются в required_stages. Ни один положительный частный результат не меняет итоговую приёмку проекта на PASS.


## Жёсткое правило отчётности

1. FAIL, NOT_TESTED, IMPLEMENTED_UNVALIDATED не переводятся в PASS без отдельного успешно выполненного приёмочного испытания.
2. Отрицательные результаты сохраняются в диагностическом журнале с причиной, но не маркируются как завершённые достижения.
3. После исправления обязательно повторное независимое измерение с версией кода, seed и данными.
4. 596 кадров с внешними эталонными позами проверяют только RGB-D обработку и геометрию, НЕ SLAM.
5. Синтетический IDF1=1.0 нельзя переносить на реальные объекты.
6. Меньше неопределённых сопоставлений НЕ означает меньше false-splits/false-merges.
7. Нет итоговой «лучшей архитектуры», пока независимый GT benchmark не пройден.

## Критерии обязательной приёмки

- Full-frame RGB-D: непустой TSDF mesh, ray-carved occupancy и известная калибровка; количественная геометрическая оценка по независимым данным.
- RGB-D SLAM: восстановленные без GT позы, ATE/RPE, loop-closure validation; полная корректировка карты после optimization.
- Object permanence: аннотированные GT instance identities, IDF1, HOTA/AssA, false-split/false-merge и re-entry accuracy; несколько сцен и ракурсов; случаи похожих и перемещённых предметов.
- Semantic memory: качество категорий, дескрипторов, референциального поиска и пространственных отношений на GT.
- Nav2: проверка достижимости и коллизий, реальный запуск планирования в ROS 2 тестовом стенде.

Предыдущая рекомендация геометрия+внешний вид остаётся гипотезой: преимущество над альтернативами по точности реальных физических ID не подтверждено.
