## Цель и гипотеза

Гипотеза H0: повторное вычисление одинакового организованного XYZ-облака для нескольких потребителей RGB-D создаёт избегаемые затраты CPU. Общее облако позволяет снизить время обработки при сохранении пиксельно-точечного соответствия и идентичной геометрии.

Это эксперимент над **нашими** кандидатными вычислительными операциями. Он не показывает, сколько раз RTAB-Map внутри себя перепроецирует глубину, и не измеряет ускорение целого ROS 2-конвейера.

## Экспериментальная среда

- GitHub-hosted Ubuntu 24.04, Docker-образ на основе `ros:jazzy-ros-base`.
- Установлены ROS 2 Jazzy и пакеты `rtabmap_slam`, `rtabmap_util`.
- Python 3.12.3, NumPy 2.5.4; CPU; без NVIDIA GPU.
- Синтетическая детерминированная глубина 640×480 с невалидными значениями.
- Две синтетические бинарные маски; калибровка fx=fy=525, cx=319.5, cy=239.5.
- 3 разогревочные итерации, 20 измерений на вариант; порядок вариантов чередуется.

## Сравниваемые реализации

**DUPLICATE:** дважды строим организованное XYZ-облако для одного изображения глубины, после чего два потребителя выбирают точки по своим маскам.

**SHARED:** один раз строим организованное XYZ-облако, оба потребителя выбирают точки из общего массива.

Контроль: совпадение координат XYZ, совпадение форм выходных массивов, отдельная проверка проекции при известном смещении 0.1 м.

## Первая неудачная попытка и исправление

Первый [запуск 41199044739](https://github.com/KiRiII-C/cv_vlm/actions/runs/41199044739) завершился ошибкой оболочки: `set -u` был включён до `source /opt/ros/jazzy/setup.bash`, и ROS обращался к незаданной переменной `AMENT_TRACE_SETUP_FILES`. Сборка контейнера тогда прошла успешно. Порядок команд исправлен, повторный запуск прошёл.

## Интерпретация и ограничения

H0 **подтверждена для данного микробенчмарка**: общее организованное облако сокращает CPU-затраты без изменений координат. Число 1.63× нельзя экстраполировать на полный RTAB-Map, TensorRT YOLOE, SLAM на датасете или производительность на RTX 4060.

**Не проверено:** реальный SLAM, одометрия, ATE/RPE, loop closure, точность карты, межпроцессная передача ROS, стоимость копирования, выигрыш от модификации RTAB-Map.
