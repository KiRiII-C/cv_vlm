# A3 — RTAB-Map pose graph optimization: честное сравнение с одометрией

**Состояние:** `RUNNING / NOT_VALIDATED` (эксперимент запущен, численных результатов пока нет).  
**Ветка:** `experiments/rtabmap-geometry-a0-20261031`.  
**GitHub Actions:** [A3 в составе A1/A2, run 41434781088](https://github.com/KiRiII-C/cv_vlm/actions/runs/41434781088).

## Мотивация

В A1 получена частичная визуальная одометрия на TUM RGB-D Freiburg1 desk; в A2 построена TSDF-карта по исходным `/odom`-позам, с пропусками и возможными разрывами. База RTAB-Map содержит граф поз и связи замыкания циклов, но сохранение ссылки ещё не доказывает, что оптимизация улучшила ATE, качество карты или локализацию после перезапуска.

Задача A3 — воспроизводимо получить **два графа RTAB-Map из одной сессии**, построить карты по **одним и тем же RGB-D-кадрам** и сравнить их, не используя GT при оценке поз или картировании.

## Реализация и источники данных

1. Пока узел `rtabmap_slam/rtabmap` работает, `scripts/rtabmap_graph_export_a3.py` вызывает `/rtabmap/get_map_data` с `global_map=true`, `graph_only=true`. Первый вызов: `optimized=false`; второй: `optimized=true`. В обоих ответах сохраняются `MapGraph.poses_id`, `MapGraph.poses`, `MapGraph.links`, frame_id. Не сохраняются тяжёлые сенсорные изображения и GT.
2. **После завершения SLAM** `scripts/rtabmap_graph_reconstruct_a3.py` сопоставляет ID узла с таблицей `Node(id,stamp,weight)` в реальной базе `rtabmap.db`. По `stamp` сопоставляет его с журналом ROS timestamps и исходной временной меткой кадра TUM. Служебные узлы с отрицательным весом исключаются.
3. Для сравнения используются только ключевые кадры с ID, присутствующими в обоих графах и сопоставленными по времени. `T_map_cam` вычисляется из полученных оптимизированных / неоптимизированных поз, а не из GT.
4. Обе версии геометрической карты реконструируются **по идентичным кадрам**: `raw_geometry` и `optimized_geometry`. Используются одинаковые TSDF voxel, разрешение, ограничения глубины и RGB-D данные.
5. Для независимой оценки поз *после* создания двух файлов поз берётся TUM `groundtruth.txt`. Для обеих траекторий считается SE(3)-согласованная ATE RMSE/median/p95 без масштабирования на одинаковом множестве узлов. TUM GT не подставляется при пропусках.
6. Анализируются связи разных типов и компоненты связности **подмножества сопоставленных узлов**, остаточные коррекции raw → optimized, доля использованных кадров. Влияние на карту определяется отдельно; количество вершин меша само по себе не равно точности.

## Критерии приёмки

- A3 graph export: оба ответа получены в работающей сессии и содержат как минимум 12 общих реальных узлов.
- SQLite-метки узлов совпадают с ROS replay timestamps в пределах 0.05 с; нет двойного назначения одного RGB-D-кадра разным ключевым узлам.
- Одинаковое множество ключевых кадров в обеих сравниваемых версиях карты. Для оценки ATE — независимый источник GT, ни при одном шаге картирования не переданный в SLAM.
- Сохранены отчёт `a3_report.json`, граф `pose_graph_service.json`, карты и логи. Отрицательный результат фиксируется как результат.
- Если `ATE_optimized > ATE_raw`, **не утверждать улучшение**. Если ATE уменьшается, это подтверждает пользу на данном датасете и подмножестве узлов, но не доказывает корректность полной 3D-карты.
- Отдельно проверять повторную локализацию после рестарта и устойчивость в динамической сцене: A3 этого не измеряет.
