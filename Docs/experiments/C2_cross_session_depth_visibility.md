# C2 — повторная проверка объектной памяти по глубине независимого RGB-D прохода

**Дата:** 2026-11-02. **Ветка:** `experiments/rtabmap-geometry-a0-20261031`.  
**Состояние:** `INDEPENDENT_DEPTH_FULL_SOURCE_PASS / C1_SURFACE_GEOMETRY_RECHECK_PASS / PHYSICAL_CHANGE_GROUND_TRUTH_NOT_EVALUATED`.  
**CI:** [C2 full TUM desk2](https://github.com/KiRiII-C/cv_vlm/actions/runs/41489070935).

## Научная цель

A8 показал успешную глобальную релокализацию на **независимой** записи `fr1/desk2`; C1 содержит **15 консервативных UUID-гипотез** с реально измеренными 3D-вокселями из B7, но их физическая идентичность ещё не подтверждена. Проверим геометрическое существование этих поверхностей в новых измерениях, не подменяя отсутствие YOLO-маски доказательством исчезновения.

Исходная B7 карта: полные **595** RGB-D-пар `fr1/desk`; **119** YOLOE-26x keyframes; **1 813 505** измеренных 3D точек внутри сегментационных масок. C1 сохранил **27 839** вокселей поверхностей в **15** UUID-гипотезах по C0 quality gates. Query-сессия: полный TUM `fr1/desk2`, **640** RGB и **639** Depth кадров; **все 639 измерений глубины проверяются и сопоставляются без прореживания**.

## Методика

1. Загрузить **без изменений** C1 PLY `hypothesis_surfaces.ply` с численным `instance_index` и `hypothesis_surfaces.instances.json` с ID гипотез. Это единственный объектный источник для пространственных запросов; уже сохранённые ID не изменяются.
2. Использовать только **фактически опубликованные** в A8 `/localization_pose` локализации `saved_last` в сохранённой карте `desk`. Для каждого принятого ROS timestamp восстановить исходный query-кадр из `full_desk2.publish.json`; **не экстраполировать** глобальную позу на 614 кадров без принятого матчинга.
3. Каждый 3D-воксель C1 перепроецировать через принятую SE(3) позу в оптический кадр новой камеры; применить z-buffer и сопоставить предсказанную глубину с **настоящим 16UC1 TUM depth** (`depth/5000`, K для Freiburg1).
4. С учётом неопределённости принятой позы увеличить допуск до `max(0.08 м, 0.035·z, 3·sqrt(max(cov_xyz)))`. Это консервативная практическая процедура; ковариация RTAB-Map не была независимо откалибрована.
5. Для каждого воксельного облака и независимого кадра различать `GEOMETRICALLY_COMPATIBLE_NOT_ID_PROOF`, `OCCLUDED_NOT_MISSING`, `FREE_SPACE_CONFLICT_CANDIDATE`, `MIXED_UNCERTAIN` и `UNKNOWN_NOT_ENOUGH_DEPTH`.
6. Не принимать несколько похожих ракурсов за независимые отрицательные доказательства: отрицательные наблюдения с близким положением и ориентацией объединяются. Состояние `VISIBLY_ABSENT_CANDIDATE_REQUIRES_ACTIVE_RECHECK` возможно только при **не менее трёх разных ракурсах** с подтверждённым свободным пространством и **без** геометрически совместимых наблюдений.
7. **Не изменять C1 SQLite**, не вызывать `MOVED` или `DELETED` по одному лишь глубинному конфликту: новая запись пока не содержит сопоставленных YOLOE/VLM признаков предметов, а физическая точность C1 UUID остаётся `UNVALIDATED`.

## Проверяемые условия

- Список исходной независимой записи строго равен 639 Depth/640 RGB, все 639 depth-файлов существуют и распознаются в оригинальном порядке.
- Число допустимых независимых глобальных поз не должно быть искусственно увеличено от более частой `/odom`; каждая принятая поза имеет исходный frame index.
- 15 UUID-гипотез, точное число C1 исходных вершин и физические координаты сохраняются.
- Все результаты evidence по каждой гипотезе и ракурсу сохраняются в `c2_frame_uuid_evidence.jsonl`; итоговые решения — в `c2_cross_session_visibility.json`.
- Невозможна автоматическая потеря объекта из-за не наблюдавшейся области или окклюзии; 8 unit-тестов отдельно проверяют ошибки свободного пространства и поведение нескольких ракурсов.

**Принципиальное ограничение:** никакого независимого GT факта реального физического перемещения объектов в этой паре TUM нет, поэтому даже технически успешная проверка не может доказать detection F1 moved/disappeared. Для перехода к C3 понадобятся заново сегментированные `desk2` маски, корректное глобальное сопоставление и отдельная объективная разметка изменений.

**Важное наблюдение:** для **всех 15** C1 гипотез есть хотя бы один ракурс, в котором новая реальная depth геометрически совместима со старой. По фиксированным консервативным правилам результат агрегирования **15/15 `GEOMETRY_SUPPORTED_AT_SOME_VIEWS_NOT_PHYSICAL_ID`**; все 9 локальных конфликтов недостаточны для удаления либо переименования объекта. Состояние SQLite C1 в эксперименте **не менялось**.

Это не доказывает, что все старые физические предметы действительно остались на прежнем месте: похожая свободная/занятая геометрия может оказаться от другого физического экземпляра. Допуск глубины увеличен с учётом некалиброванной ковариации A8, что минимизирует ложные доказательства исчезновения, но также уменьшает чувствительность к небольшим перемещениям. На query-сессии пока нет независимых YOLOE масок для физического Re-ID.

**Технический итог C2:** первая полная и проверенная cross-recording геометрическая сверка реальных C1 объектных поверхностей с независимым TUM Depth после restart/relocalization. Это `FUNCTIONAL_EVIDENCE_PASS`, но **не `DYNAMIC_OBJECT_CHANGE_DETECTION_PASS`**. Далее необходим независимый C3 запуск YOLOE-26x по принятой карте и сравнение candidate object assignment без подмены физического GT.
