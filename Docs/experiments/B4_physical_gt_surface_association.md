# B4 — проверка геометрического соответствия масок по физическим ID (100 × 3 кадров Hypersim)

**Ветка:** `experiments/rtabmap-geometry-a0-20261031`. **Статус:** `FULL_300_REAL_YOLOE26X_FRAMES_PASS / PAIR_RANKING_GAIN_MEASURED / TRACK_IDF1_NOT_EVALUATED`.
**Реальный CI:** [GitHub Actions run 41461111614](https://github.com/KiRiII-C/cv_vlm/actions/runs/41461111614).

## Гипотеза и принципиальный тест

B3 получил медианный IoU 0.711 при 30 тыс. точек и однопиксельном splat **на уже принятых short-ID парах**. Такой IoU может быть высоким и для разных физических экземпляров одинакового класса, а значит, это **не проверка Re-ID**.

B4 использует официальные RGB, 3D XYZ, semantic и semantic_instance данные Hypersim, повторно пропускает реальные RGB через **официальную YOLOE-26x-seg.pt** (12 текстовых классов), обрабатывает **все 100 последовательных кадров каждого из трёх `cam_00`**: `ai_002_001`, `ai_005_001`, `ai_017_001`. Всего 300 кадров; без keyframe decimation, без GT масок на входе сегментатора.

## Кандидаты и признаки

Для каждой пары соседних кадров создаются **все допустимые одинаковые категории предсказанных YOLOE масок**. Никакие физические GT ID не используются для подготовки индексов, вычисления признаков, ранжирования и выбора/отсечения кандидатов. Для достоверной метрики после расчёта выбираются пары, для которых исходные YOLO-маски удалось связать с эталонным физическим экземпляром по заранее фиксированному `IoU≥0.10`. Это scoring set, а не полный набор физических экземпляров; пропущенные детектором объекты здесь не оцениваются.

**Контрольная гипотеза H0:** метрическая 3D близость центров + HSV appearance (78% +22% соответственно; геометрия `exp(-0.5·(d/0.30)^2)`).

**Исследуемая H1:** тот же контроль плюс независимое свидетельство многовидовой поверхности, 75% базового score +25% surface overlap. Обе ветви работают с *одинаковыми* масками YOLO и **одинаковой официальной координатной системой Hypersim world XYZ**. Эта XYZ выступает оптимистичной oracle-геометрией в **обоих вариантах**: это чистое изучение data association, **не RTAB-Map SLAM**.

Новое значение `surface overlap` — проверка ранее измеренных 3D точек маски на наличие **наблюдаемой в текущем кадре** близкой 3D поверхности (KD-tree, допуск 4 см) и сопоставление её пикселей с новой предсказанной маской. Это **не перспективная SE3-з-буферная перепроекция B3**. Если данных для поверхностного сопоставления недостаточно (менее 8 совместимых точек), H1 использует H0 без искусственного отрицательного совпадения.

## Метрики

По всем размеченным candidate pairs внутри каждого кадра после вычисления score записываются:
- ROC AUC — различимость `same physical ID` vs `distinct physical ID`;
- average precision — важна при дисбалансе числа положительных пар;
- отдельные показатели для **всех одинаковых классов** и **сложных близких кандидатов ≤0.8 м**;
- число всех предсказанных масок/наблюдений, число реальных положительных и отрицательных пар, число случаев без поверхностной видимости.

H0 и H1 сравниваются на **строго одинаковом** наборе размеченных candidate pairs, параметры фиксированы **до просмотра результатов**, никакой подбор порога на тестовых сценах не допускается. **Эти метрики не являются трековым IDF1/HOTA** и не включают объекты, которые YOLOE не нашёл.

Исходники: [B4](../../scripts/b4_hypersim_physical_gt_projection.py), [CI](../../.github/workflows/b4-hypersim-projection-physical-gt.yml).

## Связь с литературой

- Open3DIS, CVPR 2024: https://openaccess.thecvf.com/content/CVPR2024/html/Nguyen_Open3DIS_Open-Vocabulary_3D_Instance_Segmentation_with_2D_Mask_Guidance_CVPR_2024_paper.html — объединение instance masks из разных видов через 3D согласованность.
- PanopticFusion, 2019: https://arxiv.org/abs/1903.01177 — согласование 2D instance ID с предыдущим 3D map-state.
- Fusion++, 3DV 2018: https://arxiv.org/abs/1808.08378 — отдельная 3D объектная память и отслеживание существования.

**До реального выполнения B4 нельзя утверждать, что лучшая растеризация снижает ошибки физической идентичности.**

## Реальные результаты B4 (все три job GitHub Actions успешны)

[CI run 41461111614](https://github.com/KiRiII-C/cv_vlm/actions/runs/41461111614): три независимые задачи `ai_002_001`, `ai_005_001`, `ai_017_001`, каждая **100/100 последовательных кадров**, с реальным YOLOE-26x-seg.pt и официальной Hypersim-разметкой. **Все job SUCCESS**. Физические GT ID не использовались для вычисления score или выбора геометрических кандидатов.

**Важный научный вывод:** поверхностное 3D-соответствие имеет дополнительную различающую информацию сверх центров 3D и HSV, но преимущество на близких экземплярах иногда **очень мало**. На `ai_017_001` ROC AUC поднялся всего на 0.00118. Чистое projective overlap отдельно на той же сцене **хуже** сочетания признаков для сложных кандидатов: ROC AUC **0.80567** (на выборке с доступным наблюдением). Следовательно, даже при oracle-геометрии поверхность не следует использовать вместо совместного score.

**Ограничения:** GT world XYZ в обеих ветвях — не RTAB-Map; KD-tree nearest-surface не равен перспективной перепроекции B3. Оценены пары **соседних кадров**, а не длительный re-ID после пропусков и перемещений. Эти высокие ROC AUC **не противоречат** ранее низкому физическому IDF1 в B2, потому что B2 штрафует отсутствие детекций, ошибки assignment и длительные пропуски, а B4 исключает несопоставленные с физическим GT наблюдения и оценивает только пары, для которых есть детекции в двух соседних кадрах.
