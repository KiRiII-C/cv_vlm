# C3 — независимые YOLOE-26x маски после RTAB-Map релокализации и C1 3D-памяти

**Дата:** 2026-11-02. **Ветка:** `experiments/rtabmap-geometry-a0-20261031`.  
**Статус:** `RUNNING / PHYSICAL_UUID_GROUND_TRUTH_NOT_AVAILABLE`.  
**GitHub Actions:** [C3 run 41489734662](https://github.com/KiRiII-C/cv_vlm/actions/runs/41489734662).

## Цель и гипотезы

[C2](C2_cross_session_depth_visibility.md) воспроизводимо сравнил **15** существующих пространственных UUID-гипотез C1 с **639** реальными Depth-файлами новой записи TUM `fr1/desk2`, используя **25** принятых RTAB-Map глобальных поз. Среди 375 surface-view проверок зарегистрированы 155 геометрически совместимых, но это не является подтверждением класса/физического экземпляра.

C3 впервые проверит на независимой записи **настоящие YOLOE-26x сегментационные маски**, а не только глубину. Полученные 3D-наблюдения новых классов будут консервативно сопоставлены с **ранее сохранёнными в C1** объектными поверхностями без изменения их UUID.

## Полнота и процесс

- Источник новой сессии: **полные 640 RGB / 639 Depth** TUM Freiburg1 desk2. Проверяются все 639 синхронизированных исходных RGB-D-пар (списки источника/таймстампы).
- Глобальные `T_map_camera` не придумываются, не интерполируются и не подставляются из GT. Настоящая `/localization_pose` A8 имеется только для **25 кадров**, поэтому YOLOE-26x запускается **на всех этих 25 кадрах**. Остальные 614 кадров геометрически не привязываются к сохранённым объектам.
- `YOLOE-26x-seg.pt` и прежние **12 классов**; начальный confidence ≥0.40, минимум 60 зарегистрированных Depth-пикселей, фильтрация фоновых depth-пикселей внутри маски.
- Объекты переводятся в мировые точки по измеренной глубине и принятой позе RTAB-Map через `SharedRGBDFrame`, максимум 3000 реальных точек на маску.
- Старые C1 гипотезы и 3D поверхности загружаются без модификации из `object_memory_with_surfaces.sqlite` и `hypothesis_surfaces.ply`. У кандидата обязательно должна совпадать категория YOLOE и быть допустимая метрическая близость ≤0.45 м.
- Учитываются близость центров и доля измеренных 3D-точек нового наблюдения, попавших в радиус 0.10 м от сохранённой поверхности. Оценка `0.75 exp(-0.5(d/0.23)^2) + 0.25 surface_support`, порог ≥0.48. One-to-one Hungarian по одному кадру.
- Если два старых кандидата имеют близкие оценки (разница менее 0.08), **не присваивать никакой persistent UUID**. Ненайденный кандидат **не удалять**, не считать физически перемещённым.
- Эталонные TUM GT-позы и физические GT-ID запрещены для принятия решений.

## Измеряемое

- Все 639 query source-файлов учтены; число реальных `YOLOE` inferenced кадров должно соответствовать числу принятых A8 глобальных поз (≥20; ожидается 25).
- Реальные количества обнаруженных масок, валидных 3D-наблюдений, однозначных геометрических кандидатов, неоднозначных и неопознанных наблюдений.
- Число старых C1 гипотез с новыми геометрическими кандидатами, **не** число подтверждённых физических экземпляров.
- Экспорт `c3_independent_object_candidates.jsonl`, `c3_independent_3d_masks.npz`, `c3_report.json`.
- Состояние старой SQLite памяти **не изменяется**; никакого ложного `MOVED/DELETED` без независимого физического GT.

**Недостаток протокола:** из-за редких принятых A8 глобальных поз на 614 кадрах семантическое соответствие пока не строится, даже если YOLOE потенциально могла бы их обработать. Для полноценной непрерывной реидентификации нужна доверительная map→odom траектория и covariance/pose-quality gating, а не экстраполяция неподтверждённых глобальных поз.
