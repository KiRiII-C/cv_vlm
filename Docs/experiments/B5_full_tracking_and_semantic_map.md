## B5-T: отдельная проверка краткосрочных ID по реальным YOLOE маскам и физическому GT

Исходники [b5_tracking_cadence_physical_gt.py](../../scripts/b5_tracking_cadence_physical_gt.py), [CI](../../.github/workflows/b5-full-tracking-cadence.yml), [Actions #41467827418](https://github.com/KiRiII-C/cv_vlm/actions/runs/41467827418).

Используются ранее сохранённые **настоящие** YOLOE-26x-seg предсказания на **всех 100 последовательных кадрах** каждой из 3 официальных сцен Hypersim `ai_002_001`, `ai_005_001`, `ai_017_001`. 3D-центры получены из официальных world XYZ Hypersim — **это oracle геометрия, а не RTAB-Map**. Разметка физических ID используется только при оценке; никакие GT-ID не поступают на вход алгоритму трекинга.

Сравниваются 8 конфигураций: `3d_only` и `3d_and_appearance` × интервалы реальной YOLOE-детекции **1, 3, 5, 10** кадров. Данные с пропущенных YOLO keyframe остаются в **GT denominator**, что корректно штрафует отсутствие наблюдения; исходные 300 RGB-D кадров не удаляются, только меняется частота выполнения модели. Угловые/внешние признаки 2D масок и 3D surface correspondence в этом frozen archive отсутствуют: **B5-T не измеряет влияние обновлённого B3/B4 matcher**. Цель — независимо проверить физический потолок IDF1 при разной частоте обработки.

Метрики: pooled IDF1 из IDTP/IDFP/IDFN, физические false merges/splits по каждой сцене, число измеренных кадров модели, пропуски в GT. Параметры фиксируются до наблюдения результатов; отрицательный вывод допускается. Контрольная точка: B2 при полной частоте давал **13.59%** pooled IDF1 3D-only и **14.50%** 3D+HSV на тех же frozen predictions. Отдельно нужно проверить, что B5 при stride=1 воспроизводит эти метрики — обязательный sanity check.

### Фактическая оценка B5-T на всех 300 GT-кадрах

**GitHub Actions #41467827418 SUCCESS**, код и отчёты сохранены в артефакте `b5-physical-GT-short-track-300-cadence`. Показатели pooled IDF1 вычислены из IDTP/IDFP/IDFN на всех 3×100 кадрах, без удаления кадров, в которых детектор не вызывался.

| Каждый кадр | **13.588%** | **14.503%** | 100 |

**Sanity check:** stride=1 точно воспроизводит ранее сохранённые B2 results с теми же frozen YOLOE-26x данными, 545/865/6067 и 582/832/6030 IDTP/IDFP/IDFN соответственно. Тест не содержит 2D масок и не измеряет выигрыш B3/B4 surface matching. Частота YOLO меняется, но GT-видимость и ошибки каждого кадра учитываются полностью. Эти цифры не годятся для выбора оптимальной частоты VLM/YOLOE в RTX4060 TensorRT без самостоятельного трекинга между сегментациями.

**B5-T научный итог: ID accuracy FAIL.** Работающий tracker с HSV и 3D-близостью недостаточен для физической памяти. На редких детекциях необходимо сопровождение без YOLO, при этом не смешивать transient occluders с постоянными объектами.

## B5-M: итоговая 3D-карта с фактически обнаруженными объектами

Исходники [b5_export_full_tum_semantic_map.py](../../scripts/b5_export_full_tum_semantic_map.py), [b5_render_semantic_map.py](../../scripts/b5_render_semantic_map.py), [CI](../../.github/workflows/b5-full-tum-semantic-map.yml), [Actions #41467501932](https://github.com/KiRiII-C/cv_vlm/actions/runs/41467501932).

**Одна и та же реальная сцена:** TUM Freiburg1 desk. Геометрическая база **A6 оптимизированного RTAB-Map**: все 595 RGB-D-пар учтены, 594 использованы с измеренными позами, 11 624 TSDF точек поверхности. Инференс официальной **YOLOE-26x-seg.pt** на **119 фиксированных keyframes (каждый 5-й)**, без подстановки нейросетевых масок в остальные кадры. На каждом из 595 кадров depth обрабатывается независимо. 3D точки YOLO масок обратно проецируются по глубине **того же сенсора** и переводятся в координаты оптимизированной карты с помощью реальных T_map_camera. Ни одна эталонная TUM GT поза не участвует в создании карты.

**Записи:** `b5_object_observations.jsonl` сохраняет координаты центра, 3D bbox, класс, confidence, наблюдаемую долю глубины, кадр/время и *непроверенный* short tracklet ID. `b5_semantic_pointcloud.npz` сохраняет координаты реальных измеренных 3D точек каждой предсказанной YOLO маски и классы; `semantic_map_colored.ply` — экспорт объединённой облачной карты, открываемой в CloudCompare/MeshLab; `semantic_map_highlighted.png` — 3D визуализация и XY проекция с легендой.

**Критическое ограничение:** выделенные цветом точки обозначают *нейросетевое наблюдение класса*, **не единый физический объект с доказанным persistent UUID**. Одинаковые предметы могут дублироваться, цвета могут содержать false positives, а TSDF A6 ещё не валидирована по независимой 3D геометрии. 2D occupancy A6 имеет `nav_ready=false`, поэтому изображение нельзя называть готовой навигационной картой.

## Решение о переходе к долговременной памяти C

Не присваивать устойчивые physical UUID на основании только class, маски и координат short tracker. B2 имел низкую физическую IDF1; B3 доказал артефакт неплотной перепроекции, B4 лишь небольшой выигрыш pairwise ROC AUC, не исправление ошибок полноценного трекинга. Этап C должен получать observation graph с наблюдениями, uncertainty и состояниями `MATCHED/AMBIGUOUS/UNOBSERVABLE` и проверять динамические перемещения отдельно.
