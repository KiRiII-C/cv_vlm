# B1-X — прямое сравнение официальных YOLOE-26s и YOLOE-26x в RGB-D/RTAB-Map конвейере

**Дата:** 2026-11-02. **Ветка:** `experiments/rtabmap-geometry-a0-20261031`.
**Статус:** `FULL_REAL_SENSOR_STREAM_TECHNICAL_PASS / PHYSICAL_GT_ACCURACY_NOT_EVALUATED`.

Проверены [B1, 26s run 41456143947](https://github.com/KiRiII-C/cv_vlm/actions/runs/41456143947) и [B1-X, 26x run 41457629881](https://github.com/KiRiII-C/cv_vlm/actions/runs/41457629881); оба **SUCCESS**, включая проверку всех 595 исходных RGB-D-кадров, по 119 одинаково выбранных detector keyframes, 12 одинаковых текстовых классов и тех же оптимизированных RTAB-Map-поз A6. Повторная проекция объектов осуществляется по фактической depth в остальных кадрах; **это не 595 YOLO-вызовов**, а 595 полных RGB-D-наблюдений и 119 сегментаций.

**Наблюдение:** 26x в данной CPU-среде в среднем в **7.45 раза медленнее**, чем 26s, при увеличении числа действительных 3D-наблюдений только на **0.93%** и полученных масок на **5.62%**. Улучшение reprojection IoU **не** доказывает улучшение сегментации относительно GT: сам состав выбранных объектов и коротких ассоциаций различен между двумя моделями. Уменьшение числа short tracklets 94→69 также **не доказывает** меньшую фрагментацию физических объектов — отсутствует GT физических ID в TUM. Количество `low_unassigned` увеличилось 165→264, поэтому политика уверенности нуждается в настройке под конкретную модель.

**Ограничение стоимости:** runtime — публичный GitHub Actions CPU; показатели нельзя переносить на RTX4060 TensorRT. Никаких выводов о сравнительной физической точности 26s/26x по этим данным нет. В отдельных B2 испытаниях использованы именно реальные предсказания YOLOE-26x с GT физических объектов, но там доступны только Hypersim GT XYZ, а не RTAB-Map-позы.

## Архитектурное решение для следующих B-итераций

- Сохранить единый организованный RGB-D геометрический буфер, но провести сравнение с **фактическим нативным буфером RTAB-Map**: эта ROS2 интеграция ещё не осуществлена. Не объявлять устранённым дублирование во внутреннем RTAB-Map C++.
- Развязать кадры безопасности по Depth и частоту YOLOE; частоту 3/5/10 выбирать на GT с измерением tracking IDF1/false merge/false split, не по количеству UUID.
- Сравнить на RTX4060 одинаковые веса в одном TensorRT рантайме, с одинаковым набором промптов и одинаковым resize, сохранив качество FP32 в пределах аппаратных ограничений.
- Не повышать short-track ID до постоянного физического UUID на основании одного высокого reprojection IoU или только HSV-похожести.
- Полная научная приёмка B по физической идентичности пока **FAIL** согласно B2 (pooled IDF1 только 14.50% для 3D+HSV и официальных физических GT в трёх Hypersim-сценах).
