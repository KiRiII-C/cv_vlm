# C1 — измеренные облака 3D-точек по гипотезам object UUID

**Ветка:** `experiments/rtabmap-geometry-a0-20261031`; дата 2026-11-02.  
**Источник:** исходные **1 813 505** XYZ-точек B7, сохранённые по настоящим YOLOE-26x маскам на **595 RGB-D кадрах**, и C0 evidence/SQLite память тех же **871 обнаружений**.  
**Статус:** `FULL_B7_1_813_505_REAL_POINTS_FUSED_PASS / PHYSICAL_ID_GROUND_TRUTH_NOT_EVALUATED`.  
**GitHub Actions:** [C1 run 41486402404](https://github.com/KiRiII-C/cv_vlm/actions/runs/41486402404).

## Проблема

Общая B7-карта разделена на восемь **нейросетевых категорий**, но не на физические экземпляры. C0 хранит **15 многократно наблюдавшихся гипотез UUID**, 17 предварительных и 34 неоднозначных случая, однако без предметных dense-облаков. Цель C1 — технически связать существующую память с фактическими 3D-поверхностями, не форсируя неоднозначные ID.

## Реализация

В существующий `ObjectSurfaceMemoryV2` добавлен безопасный интерфейс `integrate_world_points()`: `N×3` только конечных измеренных координат, технический идентификатор источника и исходный frame-ID; idempotent по `(map_id,uuid,source,frame_id)`, запрет совмещения разных версий графа поз. При отсутствии исходного RGB точкам **не приписывается выдуманный цвет**. В технической визуализации классы UUID окрашиваются детерминированными цветами, а не якобы истинным RGB.

[Скрипт C1](../../scripts/c1_fuse_real_b7_uuid_surfaces.py) читает последовательные B7-маски. Сумма размеров каждого среза `min(3000, mask_pixel_count)` должна равняться длине массива точек. **Каждый срез проверяется по исходной категории YOLOE и кадру**, чтобы исключить смещение точек между разными объектами. Все `871` события сопоставляются с C0 event-audit по `(frame_index,detection_id)`, идентификаторы могут присваиваться **только** тем наблюдениям, для которых C0 уже определил UUID с подтверждённой повторениями `state=confirmed`. Отложенные, неоднозначные, низкокачественные и предварительные гипотезы сохраняются в исходных артефактах, но **не присваиваются принудительно** другому объекту.

Воксели объектной памяти — **1.5 см**, `minimum_support=2`, тип `pose_version=0` от A6. Физическое `instance_gt` недоступно, поэтому цвет каждого UUID означает **гипотезу соответствия**, а не истинный идентификатор.

## Критерии

- Полный источник B7: 595 кадров, 119 YOLOE keyframes, 871 обнаружение, 1 813 505 исходных точек.
- Точное соответствие 871 source events и C0 audit; никакие исходные точки не теряются при чтении.
- Интеграция только многократно подтверждённых (но не физически верифицированных) UUID; для низкого confidence и сомнительных совпадений оставить `UNASSIGNED`.
- В одной и той же SQL базе сохранить `object_surface_v2`, `surface_frame_v2` и `objects`, запретить противоречащие pose_version; unit-тесты 3D idempotence обязательны.
- Экспортировать по-UUID облака `hypothesis_surfaces.ply` и интерактивную карту `hypothesis_clouds_interactive.html` с включением/скрытием каждой UUID-гипотезы.
- **Не присваивать статус physical-ID PASS**, пока нет независимого GT и эксперимента с перемещением реальных предметов.

## Фактические результаты C1

[GitHub Actions #41486402404](https://github.com/KiRiII-C/cv_vlm/actions/runs/41486402404) завершился **SUCCESS**; 7 интеграционных и unit-тестов успешно, 871 исходное наблюдение сверено по порядку с C0-аудитом, ни одна точка не перепутана между разными масками. Артефакт `c1-real-dense-YOLOE26x-object-hypothesis-surfaces` содержит SQLite с объектной памятью и 3D-поверхностями, `hypothesis_surfaces.ply`, `hypothesis_surfaces.instances.json`, интерактивную карту с отключаемыми UUID и исходные отчёты.

**Что доказано:** этапы B7→C0→C1 связаны на одной настоящей полной TUM-последовательности; все source points читаются в оригинальном порядке и корректно относятся к исходной маске, а измеренные поверхности можно сохранять в существующей SQLite памяти без дублирования одного кадра и без смешивания версий поз. Половина и более всех точек **намеренно остаётся без UUID-гипотезы** из-за строгих quality/identity gates. Это предотвращает выдумывание идентичности, но не доказывает высокую полноту объектов.

**Что не доказано:** выделенные 15 цветов/UUID являются 15 правильными физическими объектами. Существующая низкая физическая IDF1 на Hypersim сохраняется как ограничение. Нет GT перемещения/исчезновения, нет оценки C1 после рестарта с новой сессией, нет мгновенного Nav2 safety validation. Экспорт `PLY` использует детерминированный **технический цвет UUID**, не исходные RGB пиксели — B7 NPZ содержал XYZ, class и confidence, но не реальные RGB.

**Инженерное замечание:** B7 flat NPZ и сопутствующий JSON разрешают восстановить точки по `mask_pixel_count` только пока соблюдён исходный `max_points=3000` и порядок масок. Для последующих версий безопаснее записывать `point_start/point_end` непосредственно в `Object3DObservation`, чтобы не полагаться на неявный формат.
