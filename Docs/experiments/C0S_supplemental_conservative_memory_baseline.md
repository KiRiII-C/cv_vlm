# C0-S — дополнительный консервативный 3D memory baseline (не замена ObjectMemoryV2)

**Статус:** `REAL_300_FRAME_PHYSICAL_GT_EVALUATION_COMPLETE / ID_QUALITY_FAIL`.  
**Данные:** B5 (полные 595 TUM RGB-D кадров, 871 объектное наблюдение YOLOE-26x) и три замороженные реальные Hypersim YOLOE-26x последовательности `ai_002_001`, `ai_005_001`, `ai_017_001` по 100 кадров.  
**CI:** [GitHub Actions #41487794810](https://github.com/KiRiII-C/cv_vlm/actions/runs/41487794810) — SUCCESS.

## Почему нужен отдельный baseline

В репозитории **уже существует** реализованная объектная память `ObjectMemoryV2` и её полноценная C0→C1 интеграция с SQLite. Новый `ConservativeObjectMemory` **не является новой продукционной подсистемой и не заменяет её**. Это изолированный контроль для проверки того, помогут ли более строгие однозначные геометрические ворота, отказ от сомнительного ID и скользящие 3D прототипы поднять точность физической идентичности.

Алгоритм использует confidence≥0.35, bounded 3D distance gate≤0.42 м, 3D размеры, one-to-one Hungarian, опциональный HSV (когда frozen predictions содержат признаки), ambiguity margin 0.075. GT физические ID не использовались при сопоставлении. Состояния `UNKNOWN` и `AMBIGUOUS` не становятся удалением объектов. Код: [модуль](../../src/semantic_map/conservative_object_memory_c0.py), [evaluation](../../scripts/c0_real_observation_memory.py), [8 тестов](../../tests/test_conservative_object_memory_c0.py).

## Фактические данные

На B5 TUM обработаны все 595 кадров и 871 исходное YOLO-наблюдение (119 detector keyframes). Создано **31 предварительная гипотеза**, из которых 20 получили≥3 наблюдения; статусы исходных наблюдений: 381 matched, 31 new provisional, 453 low confidence, 6 ambiguous. Это **не** число физических объектов.

На трёх реальных frozen Hypersim последовательностях общей длиной 300 кадров:

| Сравнение | 3D only | 3D+HSV |
|---|---:|---:|
| IDTP | **458** | **458** |
| IDFP | **500** | **499** |
| IDFN | **6154** | **6154** |
| pooled physical IDF1 | **12.100%** | **12.102%** |

Этот строгий baseline **не улучшил** полученный ранее B2 YOLOE physical IDF1 **14.50%** для другой краткосрочной 3D+HSV схемы, хотя обе оценки проведены на одних и тех же трёх frozen GT последовательностях. Различаются сами правила ассоциации и политика появления/непоявления кандидатов; это не сравнение в пользу установки новых настроек.

**Решение:** оставить C0-S как исследовательский *негативный контроль*, **не интегрировать вместо действующего ObjectMemoryV2**. Не трактовать снижение числа неверных слияний за счёт неопределённости как рост IDF1 без отчёта о пропущенных физических экземплярах. Существующие C1 UUID и их 3D поверхности не мигрируются на эти новые кандидаты.

Артефакт `c0-real-595-TUM-300-Hypersim-conservative-memory` содержит полный `c0_report.json`, `c0_candidate_landmarks.json` и исходные candidate assignment events.
